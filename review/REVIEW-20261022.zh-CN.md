## 补充修复(2026-10-22 下午,CI 首次 build-captured 实测后)

GitHub Actions 首次真实运行(run 39721536545,Xcode 26.6 / Apple Clang 21)在第一个对象
`ubc_subr.o` 编译处按 fail-closed 设计停止,首错为恢复工作区缺少
`build/xnu/ios-obj/san/kasan-blacklist-arm64`(捕获命令 `-fsanitize-ignorelist` 引用;
原 Mac 构建产物,69MB 备份未收录)。穷尽核查 11 个对象捕获命令的全部工作区引用后:

1. `kasan-blacklist-arm64`:XNU 固定源归档内有 `san/memory/kasan-blacklist-arm64`,
   `prepare_mac_workspace.py` 现在恢复时从源补拷该文件(不改捕获命令本身)。
2. `EXPORT_HDRS/libsa`:备份只收了 8 个 EXPORT_HDRS 目录中的 7 个;libsa 为独立
   引导代码,内核/bsd/iokit TU 不从中包含头,恢复时创建空目录消除
   `-Wmissing-include-dirs` 警告(语义与缺失等价)。
3. `restore-test.sh` 升级为穷尽检查:恢复后验证 11 个对象捕获命令中**所有**
   OLD 前缀引用在恢复树中存在,当前结果 `ALL_OLD_PREFIX_REFS_EXIST=1`。
   该脚本同时改为按自身位置解析批处理包根,不再含本地绝对路径。

CI 用的脚本来自公共仓库(zzweiqing/hackios-mac-batch),私有 release 只提供
inputs/+capture/,因此本修复只需推送公共仓库,无需重传 85MB 输入包。

第二次 CI 运行(run 39722300689)11 个对象全部编译通过(含 IOKitBSDInit.cpo 与
kernel_tests.o,Apple Clang 21),失败推进到链接:三个未定义符号
`___chkstk_darwin`/`___llvm_profile_get_size_for_buffer_internal`/
`___llvm_profile_write_buffer_internal`。原因:`.LDFLAGS` 末尾的 `-lcc_kext`
被脚本滤除,而 `-nostdlib` 又阻止 driver 自动补 runtime。修复不是恢复
`-lcc_kext`:当前 SDK(Xcode 26.6/iPhoneOS 26.5)的 libcc_kext.a 实现 LLVM21
12 参 profile buffer ABI,与 XNU 10063 源码的 6/7 参声明同名不同 ABI,链接能过
但运行不匹配。改为链接项目自建 LLVM 17 内核 runtime
(`runtime/libcompiler_runtime_kernel.a`,15,376 bytes,三符号真实实现,
LLVM Apache-2.0 开源衍生非 Apple 材料,可入公共仓库;与 WSL 验证链
nabu-mockfs-pan1-console-probe 链接的是同一份归档,该闭包已证明无未定义符号)。
溯源见 `runtime/PROVENANCE.zh-CN.md`。
